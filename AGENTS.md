# Writing guidance

Apply these rules to comments, documentation, README files, and other written content:

- Write for the reader's context. Do not refer to private conversations, local experiments, internal nicknames, or unexplained terms the reader would not know.
- Assume readers are competent and understand the code. Explain the purpose, requirements, and non-obvious behavior without explaining routine programming concepts.
- Keep instructions direct. Avoid excessive tips, tooltips, reminders, and repeated advice.
- Use plain, precise language. Include background only when it is needed to understand or use the project.
